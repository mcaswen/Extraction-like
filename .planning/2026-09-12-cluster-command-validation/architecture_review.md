# Cluster 指令验证：规划架构自审

日期：2026-09-12。对象：[task_plan.md](task_plan.md)。状态：**规划已获确认，P0、P1a 实施审查完成；后续阶段继续。**

## 1. 需求与事实

- 用户明确只看 Cluster，已排除 Zone。正式入口是 PlayerInputManager → Dispatcher；旧 DB 点击脚本和 Room/Zone 原型没有被当成当前生产链。
- 实际场景通过 TargetInputManager Prefab 接入，AgentId 留空使用焦点。方案包含焦点和显式路由对照，不把只给固定 AgentId 下令视作覆盖默认玩家行为。
- Picker 排除 EnemySource，验证仅纳入资源、活跃敌人和撤离群。绕过鼠标意味着不覆盖命中和 UI 遮挡，报告必须保留这个边界。
- R-C1/R-C2 是源码风险，尚无本轮红灯；远敌首次接近和群后备候选作为建议行为供 Review，不能由测试先行悄悄决定玩法。
- 敌人群当前绑定具体成员，未扩大为清群队列。战死和满包规则沿用用户已确认约定。

## 2. 文件和依赖

## 3. 测试与证据

- 明确区分构造布局、真实场景命令和自主尾段，不把构造 Warp/人工伤害伪装成自然整局。
- Accepted 只表示接收，步骤还需执行和终态证据。有限连发结束后检查最新任务有进展，不把无限重试当解锁手段。
- 选择规则、近远定义、触发条件、预算和预期结果先固定；实际场景没有候选时记覆盖不足，不修改阈值或筛掉失败对象。
- 启动器完整归档脚本，显式序列化深度、版本和哈希，Editor/Player 消费同一配置；往返探针检查深层步骤没有被截断。
- 负例预期拒绝仍计入原始事件；未知 Failed、误路由、错误原因、重复结果和丢事件均会失败。先验证报告反例再跑正式矩阵。
- 直接撤离不能假定无库存，需记录预置装备和各角色携带状态；不以最终仓库反推预期。只读快照缺失时报告失败。
- 死亡允许正常终态，不自动补齐未执行步骤；通过固定独立构造弥补覆盖，不提高生命或筛选生还种子。
- 4×用于逻辑，1×用于关键时序和平均 FPS >60，保留慢帧和运行/暂停分项；不扩大为全硬件、全部输入序列无 bug 承诺。
