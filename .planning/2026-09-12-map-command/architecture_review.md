# 地图指挥实施架构审查

## P0 场景和契约基线

- 复用既有 SC00 和保留 Editor，未引入第二套启动/审计框架；Unity 解析的 Prefab 引用与实例覆写是场景证据来源。
- 规范图节点身份与运行时 TargetId 分开。已定位群 Prefab 的重复 ID，规划中的场景直接引用和 GlobalObjectId 可避免布局指向随机运行 ID。
- 保留 EnemySpawnPoint 和 Source/ActiveCluster 的出生、注册、完成所有权；记录来源配置优先于出生点直接引用，不在地图层创建敌人。
- 明确静态审计不能证明全部导航可达，锚点/双向路径验证移交 P1/P2 的共用查询，避免误报。空 Zone 保留，既有两个 Missing Script 仅记录，不无依据删除。
- 本阶段只改文档，不存在新增生产耦合或公共接口改变。SC00 证据 PASS，源输入未变；并未宣称新地图功能或整局验收通过。

结论：P0 完成；后续阶段继续检查职责边界、程序化验证及实际截图。证据见 `p0_execution.md` 和 `scene_baseline.md`。

## P1a 纯图拓扑和成本

- `IMapGraphCostProvider` 隔离成本策略，`MapGraphCostSnapshot` 仅复制边 ID/方向/数值，不依赖 Agent、Targets、NavMesh、UI 或 Editor。旧配置成本在明确兼容适配器中保留，正式导航数据不会混进显示线长。
- `MapGraphService` 保有图索引、拓扑诊断和只读邻接表；`MapGraphPathfindingService` 只搜索，工作区实例私有、不支持并行重入，返回结果与工作区隔离。未给 Overlay/AgentPawnRoot 堆入图算法。
- 同成本取点依固定 Ordinal 索引；零成本环不写回已访问节点。先校验图及端点再允许空路径完成，负数/NaN/Infinity 成本被屏蔽，不可达不返回部分可执行序列。
- 测试使用独立简单路径枚举核对 500 个组合，并验证旧图、坏拓扑、方向和别名。没有调用同一 Dijkstra 计算预期结果，也没有用测试驱动推进生产路线。
- 10 个定向用例全部通过，既有投影调用编译兼容。改动仅位于已确认 Runtime 文件边界及 Editor 测试/清单，没有生产场景/Prefab 改动。当前阶段没有可见样式变化，不重复截图旧地图。

结论：P1a 审查通过，继续 P1 的序列化/共用导航能力。

## P1b 共用导航查询

- 导航 profile 和数值结果拆为各自的数据文件，SegmentQuery 只执行采样/路径/长度测量，旧 Query 保留 readiness 和 arrival。没有把路径计算塞进图算法、生成器、PawnRoot 或 UI。
- Profile 独占复制的成本数组；公开结果不带可变 Path；原生路径及角点由调用方 Buffer 独占。旧 CombatApproach/NavigationMotor 通过兼容入口继续读取部分路径和诊断，未引入静态全局路径缓冲。
- live 查询继续使用 Agent.CalculatePath，静态查询使用完整 profile filter，避免丢失每角色区域成本。地面角点到达语义保持，fallback 的 baseOffset 包含实际缩放。
- 测试独立构造高成本区域、断岛、坡面和错误楼层，验证实际路径改变及数值长度；原导航、真实场景记录路径和部分路径交战共 36/36 PASS。原 Profiler 计数仍一调用一样本，预热段查询不分配。
- 新增 API 没有改变移动或任务所有权，文件边界符合 P1b 小规划；无资产替换、无可见样式变化。P1c 数据结构先记录规划，后续生成/运行态仍由各自模块负责。

结论：P1b 审查通过，继续 P1c。

## P1c 地图序列化契约

- Zone、生成设置、人工约束、导航烘焙数据各有独立文件，Config 不查询场景或 Agent；地图的本地显示位置和实际导航锚点分离。节点/边修改返回新对象，集合复制并提供只读视图。
- 正式图 schema 2 显式写入，历史资产保持 schema 0；未知版本拒绝。事务替换先准备集合、检查必要参数，再更新版本；失败不改变原图。运行时没有正式数据写回入口，旧 MVP 显式操作继续保留。
- 行列保存全图坐标约束，节点保存 Zone 内偏移；Service 统一换算，区域移动不改变路径成本。人工禁连记录不混入可走边，不存虚拟节点或折点。
- 导航不可达通过双向有效性和失败原因保存，反序列化不把失败变成零成本。嵌套数据的只读缓存随反序列化刷新；静态样式数据没有混入原生 NavMeshPath。
- 最终保存/重读等 8 个数据用例、10 个图算法回归全部通过，GUID 和旧资产保持。具体几何冲突/导航输入一致性将由 P2 校验器和 P1d Binding 层负责，不让纯 SO 构造器代替世界校验。

结论：P1c 审查通过，继续 P1d。

## P1d 场景绑定和成本缓存

- Binding 只拥有直接引用、锚点和索引，成员/来源群语义留给 P3 Resolver。引用匹配不使用运行时重命名 ID，兼容 ID 查询只在必要时 O(N) 读取当前 ID 并拒绝歧义，不引入失效的 ID 长期缓存。
- NavigationCostService 是唯一成本烘焙适配/本局补算责任，不兼任路径搜索、移动或 UI；Editor 候选测量也复用该入口与 SegmentQuery。首次有效烘焙载入 0 次路径查询，后续预算显式控制，不运行全对 Update。
- 新快照通过复制隔离旧值；失效立刻撤下成本。图/绑定配置替换后旧服务停止工作，组合根必须创建匹配版本的服务，避免旧边补算结果进入新图。锚点变化只使相关边进入队列。
- 失败方向显式诊断，首版双向边要求两方向都完整。数据缺失不退回图线长、不以群中心任意投影掩盖丢失绑定。运行时不使用 Editor API，不回写 SO。
- 11 个定向用例全部通过，场景用户改动保留且不混入提交；尚无新可见地图，持续截图从 P2 生成预览开始。

结论：P1d 审查通过，P1 基础能力完成，进入 P2。

## P2a 场景采集和导航矩阵

- SceneSnapshot 保存 Editor 的稳定输入，Collector 只读实际场景/Prefab/导航资产，Scan 独立管理采样、初始可达检查、双向边查询及预算；不把布局、保存或任务推进混入采集器。
- 出生随机/实例化仍归 EnemySpawnPoint；新增只读候选入口复用原有 3 米采样实现，未改真实出生规则。资源接近几何和群地表投射各自在原作者组件提供只读入口，没有测试驱动反向依赖。
- Editor 未绑定的 NavMeshAgent 不能读取实例区域成本，改读序列化配置及项目成本；与实际 Agent 的运行时 profile 一致性仍由 P1d 成本层校验。没有为了 Editor 查询创建或移动假 Agent。
- 独立断岛反例发现并修正“第一个合法采样就是锚点”的不足；先验证初始可达，所有候选均不可达则据实保留孤岛状态。宽半径失败探针只写测试证据，不能进入正式候选接受或图连接。
- 最终 4 项定向测试通过，源场景两处用户修改完整保留，未修改 Scene 或 Prefab。实际 756 次有向边查询完整，不等于每条边都可走；龙骨礁撤离孤岛事实已写入实施结果，后续生成必须保留其身份和断连诊断。

结论：P2a 职责与已确认边界一致，追加真实出生链 2/2 PASS（`20260912-210301-176`）。继续几何校验和布局生成，尚无正式可见地图或路线玩法验收结论。

## P2b1 布局验收和评分

- 生成草稿复制 Config 集合，Graph 复用现有拓扑索引；Editor 的待验收数据不直接写 SO。几何原语、错误结果、人工意图规则、导航矩阵和评分各自独立，避免万能生成器自报成功。
- 校验器只读取确定坐标及对齐身份，不给斜线自动补弯、不增加虚拟节点、不因一般交叉创建可换乘连接。数值/矩形/端口宽度和留白先拒绝非法输入，样式不能越过合法端口。
- 人工锁、人工或样式覆写边、禁连记录分别校验；显式编辑可选择本次必须保留的规则，固定拓扑重排额外要求节点和边身份不变。节点来源/Zone/类型不能通过布局修改偷换。
- 导航矩阵验收不查 NavMesh、不用显示长度，按同一 profile 的实测双向可达分量对照结果拓扑；物理断连、人工禁连、矩阵缺失和求解丢桥有不同诊断。
- 20 项独立构造通过；测试没有调用生成器来构造“预期合法”结果，跨线不可换乘又以现有 Dijkstra 验证。评分保持只读，与正式路线成本隔离。

结论：P2b1 审查通过，继续参考布局、横竖求解和联合连线。此时没有可运行的新地图或新的视觉验收结论。

## P2b2 固定拓扑横竖求解

- LayoutGenerator 负责世界参考/既有布局/坐标回写，OrthogonalLayoutSolver 只分配方向和端口，LayoutCoordinates 只解连续约束，ZoneLayout 独立满足矩形包含及中央名称空位。没有方向搜索查导航、坐标求解改边、Editor 修改实体位置等职责泄漏。
- 对齐组复用 P2b1 配置和校验，不以迭代收敛标记代替独立验收；输出仍是原节点和固定边集。节点/区域/行列锁冲突返回诊断，取消不发布部分布局，状态和坐标迭代均有明确上限。
- 记录并修正行列锁别名漏洞：原锁的成员关系也必须保持，不能把节点改绑新行后留下无用锁条目。此规则归人工意图校验器，没有分散到求解器或 UI。
- 9 项纯求解构造、21 项受影响几何/意图回归通过；同输入不同 Advance 预算得出同一结果。真实场景固定种子仍待独立诊断，不能以构造通过宣称全图求解成功。

结论：P2b2 审查通过，继续真实骨架和联合生成；正式地图与 HUD 尚未替换。

## P2b3 真实固定骨架诊断和场景修正

- 场景测试只读 Collector/Scan 结果，测试内 MST 是待验证种子，不是生产连线规则。诊断用例即使有界搜索失败也只能证明证据采集完成；只有非空布局经过独立几何/导航校验才报告固定种子可行。
- PNG 工具只消费 Unity 导出的数据，使用项目字体绘制审阅图，不查询场景、不影响生产玩法，也不冒充 Unity HUD 截图。生成后实际打开检查，保留调整前后的图。
- 用户明确修复错误空“渔村2”后，采集基线改为 7 Zone、28 群，撤下围绕错误空区域拟议的算法调整。场景文件全部用户改动保留、不混入提交；一般空区域构造能力仍保持。
- 采集 4/4、修正场景固定种子诊断 1/1 PASS。当前可画但方位仍有失真，进入联合候选比较；龙骨礁撤离孤岛仍按实际导航报告，不虚构可达边。

结论：P2b3 诊断阶段审查通过；不把 5 项通过扩大为完整地图、路线玩法或性能验收。

## P2b4 联合骨架比较和求解工作预算

- `MapGraphConnectionCandidates.cs` 负责测量快照/共同可达索引，`MapGraphConnectionSeedBuilder.cs` 负责人工意图和候选边选择，`MapGraphConnectionGenerator.cs` 编排求解、独立验收、评分和发布。三者均为 Editor 模块，不查询 NavMesh，不移动实体，不拥有运行时任务或把地图距离写成导航成本。
- 生成先保留手工边及任何样式覆写，应用禁连记录，再筛四端口；筛掉必要桥必须由每 profile 的连通验收拒绝。共同候选不足以保持各 profile 分量时明确报告，不用某一个 profile 的成功覆盖其他角色失败。首版共用图的这一冲突不会被静默转成有向图。
- 输入节点/区域/边规范排序，测量按无向端点归一，同输入换枚举顺序或 Advance 步长结果相同。候选输出经过原人工锁、几何、完整导航矩阵验收，不把部分求解当正式结果；一般线交叉不新增逻辑节点。
- 性能审查发现并修正完全相同坐标状态的重复迭代，精确值复核哈希冲突，不放大几何容差。持续漂移类候选仍由单候选和每种子坐标预算控制；状态预算不能代替坐标工作预算。取消清掉结果，预算正常结束可以保留已经验证的最佳候选，两者有独立构造证明。
- 实际四种策略比较最终选择 Geographic，2.45 秒工作、0 新导航查询，几何通过但保留物理撤离孤岛。强次轴策略预算耗尽，报告未解；不能声称全局最优或相同搜索空间提速。P2c 前仍需将连续候选按迭代切片，本轮最大 Advance 675 ms 尚不适合作为窗口交互验收结果。
- 最终真实场景 2/2、联合候选 10/10、固定求解 11/11 PASS，共 23 项。第三张静态预览已实际查看，方位改善；正式 HUD、美术缩放、编辑持久化和 Agent 路线另行验收。场景及 NavMesh 全部用户修改保留，未混入提交。

结论：P2b4 职责和接口扩展符合已确认 Editor 生成边界，阶段审查通过。P2b5 继续补边和交互分批，再进入正式编辑器接入。

## P2b5a 连续求解分批

- 坐标工作区保留自己的准备、迭代和完成状态，Solver 在搜索叶子中逐轮推进；没有把数学规则复制到窗口或联合生成器。公开 Advance 的预算单位明确为工作项，方向状态和坐标迭代分别计数。
- 每工作项最多一个方向状态或一次坐标迭代；取消时依次释放外层搜索和内层坐标任务，不能留下后台求解或发布部分草稿。预算正常结束保留有效结果的原规则保持。
- 固定求解 12/12、联合候选 10/10、真实场景 2/2 PASS，共 24 项；真实输入、生成几何、对齐约束、搜索/迭代数和最终得分与前版完全一致。单次 Advance(8) 最长由 675.20 ms 降到 22.43 ms，总工作约 2.47 秒。
- 本步只拆分调度，沿用已实际检查的第三张预览；未改玩法、资产或用户场景。后续窗口进一步使用短时间片，生成耗时数据不代替游戏帧率验收。

结论：P2b5a 审查通过，继续可选补边。

## P2b5b 实测绕路收益补边

- `MapGraphShortcutGenerator.cs` 独立管理可选边排序、有限重排和接受规则；`MapGraphConnectionGenerator.cs` 只编排，`MapGraphConnectionCandidates.cs` 提供冻结方向成本，复用原 `MapGraphPathfindingService.cs`。没有另写 Dijkstra、查询 NavMesh 或修改运行时路线所有权。
- `MapGraphLayoutGenerator.CreateAlignedConnectionDraft` 只生成待验草稿，不能绕过硬约束；共享行列身份、锁定成员关系、节点/名称留白都由独立校验器验证。补边不删骨架、不更改禁连或样式，前一条补边改变路径后必须重新计算收益。
- 方向状态和坐标迭代受原总预算及额外坐标池限制，取消释放内层任务并丢弃临时结果。普通预算结束可以保留已经有效的图，发布时明确警告，不将预算耗尽称为数学无解。导航与布局优劣分开，实测路线收益不能靠旧显示 LengthUnits 得到。
- 补边构造 9/9、真实场景 2/2、联合候选 10/10 PASS，共 21 项逻辑验证。最后一轮隔离 Editor 退出挂起已由 runner 清理，基础设施异常保留；没有重复运行已经通过的逻辑来掩盖退出问题。
- 第四张预览实际查看，28 条横竖边、0 交叉、名称留白保持。新增两条边减少绕行，但位置评分略增，属于明确受限的路线/布局取舍。源场景和 NavMesh 均未写入本提交。

结论：P2b5b 审查通过，P2b 算法阶段完成。P2c 接入窗口时继续验证操作预算、过期结果和事务保存；正式 HUD 与玩法仍未接入。

## P2c1 编辑器生成任务

- `MapGraphGenerationController.cs` 持有一次任务的阶段、取消和统计，复用扫描及求解组件，不订阅全局 Update，不写资产或运行时任务。`MapGraphGenerationResult.cs` 只读复制测量集合并关联请求/文档版本；发布前和应用前重新采集输入。
- 固定布局模式使用原边集，独立验收再次要求拓扑保持。旧节点/区域的身份删除或归属变更返回同步诊断；即使空区域未锁定也不能被静默丢弃。新增节点不能借“仅重排”进入原图。
- 设置在任务开始经 Unity 序列化复制，工作项和时间预算同时生效，扫描单批另有限制。取消逐层停止任务，不依赖窗口还在运行；失败和过期结果不公开可应用草稿。
- 场景指纹由原 Collector 统一补齐名称、中心、层级/Prefab 来源、Agent profile 和初始位置，Controller 不维护另一套场景字段比较；后续作者文档负责自己的编辑版本，不能用场景指纹替代文档版本。
- 13/13 定向验证通过，真实任务最长推进 13.25 ms；采集/校验原子工作可能超过 6 ms 时间片，计数如实记录。源 Scene/NavMesh 无写入，无新可见 UI，因此不重复截图。

结论：P2c1 审查通过，继续文档事务及窗口。当前只完成计算任务，不把取消安全等同 Undo/持久化已完成。
