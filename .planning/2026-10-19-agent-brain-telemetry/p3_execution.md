# P3 撤离树：执行记录

目标见 [大规划](task_plan.md) 第 4.3 节和第 8 节 P3。

## 1. 旧树行为

记忆式序列：`MoveToTargetActionNode`（撤离、撤离群、交互距离、默认 1.5）→ `ExtractActionNode`。

撤离节点每帧：取智能体 → 取撤离指令（不检查目标类型）→ 解析具体撤离点（直接指向的撤离点，或撤离群里最近的点；解析不到就按目标无效结束指令并失败）→ 移动（交互距离）→ 未到达时撤销"在点内"登记并返回运行中；到达时向 RaidFlowController 续写"在点内"，永远返回运行中。退出和中断时撤销登记。

记忆式序列的含义：前一段到达后，同一帧接着执行撤离节点，此后每帧只执行撤离节点；到达那一帧移动会被调用两次。

## 2. 新树

```
撤离（记忆式序列，与旧树相同）
├─ 前往撤离点（响应式序列）
│  ├─ 条件  智能体可行动
│  ├─ 条件  持有撤离指令（撤离点）
│  ├─ 动作  解析撤离点目标点
│  └─ 动作  移向目标点（交互距离）
└─ 驻留撤离点（响应式序列）
   ├─ 条件  智能体可行动
   ├─ 条件  持有撤离指令（不限目标类型，与旧节点一致）
   ├─ 动作  解析撤离点          解析不到按目标无效结束指令
   ├─ 动作  移向目标点（交互距离）
   └─ 动作  登记在撤离点内      每帧续写；退出或中断时撤销
```

"未到达时撤销登记"不再写在节点里：移动节点返回运行中时，响应式序列在它返回之后中断排在后面的登记节点，登记节点的中断回调撤销登记，时机与旧节点在同一帧、同一位置撤销一致。解析失败、指令消失、智能体失效时，响应式序列同样会先中断登记节点（撤销）再返回失败，顺序与旧节点"先结束指令、退出时撤销"一致。
