# P5 搜索树与删除 InteractLoot：执行记录

目标见 [大规划](task_plan.md) 第 4.3、4.4 节和第 8 节 P5。分两步提交：先迁移搜索树并对拍（保留旧的黑板写入），再删除 `InteractLoot` 和 `HasInteractableTarget`，处理旧节点去留。

## 1. 旧节点

记忆式序列：移动到最近的未处理成员（交互距离）→ `SearchResourceActionNode`。搜索节点内部每帧：取智能体和搜索指令 → 同步目标（目标切换时清掉到达、等待、完成音效标记）→ 按目标形态分三路：

- **资源群**：找最近的可达未处理成员；找不到时，群里没有待处理成员就完成搜索，否则以"不可达"结束指令并保持运行中；换成员时清掉到达和等待状态；处理该成员；成员处理成功后，群里没有待处理成员就完成搜索，否则清掉成员状态、保持运行中，下一帧找下一个。
- **抽象点**：解析位置（失败则失败）→ 移动（未到达清等待状态）→ 停步 → 完成搜索。
- **具体对象**：直接处理该对象，处理完即完成整条指令。

处理单个成员：对象不存在就结束；定位停靠点（失败则失败）并在换资源时上报"接近中" → 移动（未到达时清等待、上报接近中，刚离开范围时关掉本人为它打开的背包）→ 停步 → 箱子：推进航天零件节奏、生成战利品，桌游点已搜空、本轮已处理、空箱则登记并完成本成员，否则等待背包；地面物品：已处理、无效则登记并完成，否则等待背包；其他对象直接结束。

等待背包：上报"等待背包" → 没有背包控制器则保持运行中 → 第一次等待该资源时通报触碰 → 匹配本人为该资源打开的会话 → 会话关闭前保持运行中 → 容量不足时登记、通报完成、标记需要撤离、上报容量不足并完成整条搜索；否则登记并完成本成员。

进入时重置搜索状态；退出时按结果上报完成或离开并重置；中断时上报离开并重置。

## 2. 新树

```
搜索资源（记忆式序列，与旧树相同）
├─ 前往资源（响应式序列）：可行动 → 持有搜索指令（资源）→ 解析目标点 → 移向目标点（交互距离）
└─ 搜索记忆（作用域：进入重置；退出按结果上报完成或离开；中断上报离开）
   └─ 处理资源（响应式序列）
      ├─ 条件  智能体可行动
      ├─ 条件  持有搜索指令
      ├─ 动作  同步搜索目标（同时判定目标形态）
      └─ 按目标形态（响应式选择器，三个分支都带形态守卫）
         ├─ 资源群：条件 目标是资源群 → 动作 解析下一成员 → 成员处理结果（响应式选择器）
         │   ├─ 群已处理完 → 完成搜索
         │   ├─ 成员走不到 → 判定不可达（保持运行中）
         │   └─ 处理当前成员：切换当前成员 → 处理单个成员 → 成员完成后
         ├─ 抽象资源点：条件 → 解析抽象资源点 → 移向抽象资源点 → 完成搜索
         └─ 具体资源：条件 → 指定具体资源 → 处理单个成员

处理单个成员（响应式选择器）
├─ 成员已不存在 → 结束本成员
└─ 到场处理：确定成员停靠点 → 靠近成员 → 按成员类型（响应式选择器）
    ├─ 箱子 → 处理箱子（检查箱子 | 等待背包）
    ├─ 地面物品 → 处理地面物品（检查地面物品 | 等待背包）
    └─ 其他对象直接结束

等待背包（响应式序列）：上报等待背包 → 等待玩家开关背包 → 会话结果（容量不足收尾 | 关闭后收尾）
```

**交互上报的顺序**：上报、结束上报、清等待状态、完成搜索等操作都原样搬进 `AgentSearchMemory`，节点只决定何时调用，发布顺序与旧节点相同。

**守卫**：旧节点的三路形态互斥，某一路失败时整个节点失败。新树三个形态分支都带守卫条件，防止资源群分支失败时落到"具体资源"分支、把群对象当成具体资源处理。

**"成员完成后"返回运行中**：与旧节点一样不退出子树，下一帧从头找下一个成员。若改成先成功退出再进入，搜索记忆会被作用域重置，完成音效的去重标记随之清零，行为会变。

## 3. 删除 InteractLoot 与旧节点去留

- 删除 `AgentMacroStateId.InteractLoot`（值 4），其余枚举值保持显式数值不变；删除其状态、搜索资源指向它的转移、它的四条出边、两条进入/离开规则和状态工厂方法。
- 删除黑板键 `HasInteractableTarget`，以及它的全部写入点（生命周期、智能体初始化、决策、发现、搜索收尾）和没有调用方的设置接口（智能体、指令接收器接口、命令路由的两个重载）、调试视图字段和 I 键打印中的字段、Agent 预制体里残留的序列化值。
- 转移规则"资源工作可被战斗打断"里的 `!hasInteractableTarget` 恒为真，化简为 `!hasResourceTarget && 持有交战指令`。这条规则由 Lifecycle、ManualDirectiveResume、SceneRetaliation、ClusterCommandTransition 等组覆盖，不单独写真值表测试。
- 删除的转移条件都是只读黑板的纯函数，状态机少求值它们不改变行为。
- **旧节点去留**：四个旧动作节点和 `AgentLegacyBrainTrees` 改为只在编辑器中编译（`#if UNITY_EDITOR`），正式构建里不再存在；编辑器里继续作为 `BrainTreeEquivalence` 的对照，对拍因此能长期保留，不需要另存录制文件。旧搜索节点同样去掉了对已删除黑板键的写入，与新树保持一致。探索树的占位节点 `MaintainMacroStateActionNode` 本身就是正式探索树，保留在运行时代码中，构建方法移入 `AgentBrainTrees.Explore`。
- `ResourceCommandCompletionTests` 原来直接构造旧移动节点，改为执行正式搜索树的"前往资源"分支。
- 文档：框架设计文档的宏状态、装配、转移规则、执行节点四处更新；`outputs/agent_ai_framework_diagram.md/.svg` 去掉 InteractLoot（两份框架图仍画的是重构前的树结构，P11 统一重画）。
