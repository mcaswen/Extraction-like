日期：2026-10-19。源码基线：`d378512`（dev）。状态：**P0–P7 已完成（各阶段证据见 `p0_execution.md`…`p7_execution.md`），P6 性能余差（发布优化下战斗 +8%、搜索 +4%）用户已接受；P8 用户选定录制布局（精简版）并已实现，待重建字体和桌面目视验收（见 `p8_execution.md`）。** 大阶段定义见第 8 节。每个大阶段开工前另写 `pN_execution.md` 小规划，完成后在其中记录证据。

## 1. 功能模块概述

### 1.1 要做成什么

为评委展示和宣传视频做一套"看得见的智能体大脑"。它由四部分组成：

1. **行为树重构。** 把现在每个状态里一两个"大动作节点"拆成真正的细粒度行为树：条件、动作、组合节点、装饰器各司其职。拆完后游戏行为必须与现在等价。
2. **大脑遥测面板（B 键）。** 界面风格与科普档案一致，实时显示焦点智能体的大脑：
   - 分层状态机：当前状态，以及当前状态各条出边的实时条件与优先级；
   - 当前状态的行为树：每个节点的运行、成功、失败；
   - 指令槽：活动槽和挂起槽；
   - 目标评分表：每个候选群按公式拆项，被排除的写明原因；
   - 事件时间线。
3. **三维叠加层（U 键）。** 在游戏世界里直接画出"看得见、走得到、打得着"：视线射线和遮挡物、接近点的两圈候选和最终选点、导航路径、决策图路线。
4. **现场导演。** 在正式场景 `Scenezl_Final 1` 里摆好条件，真实触发三个典型场景：
   1. 自主选目标；
   2. 遇袭挂起后恢复同一条命令；
   3. 指挥员干预，覆盖自主路线。

   面板配合"三步原理演示"逐步讲解，同时留下事件记录。

### 1.2 使用对象和发布范围（用户已确认）

- **只给评委展示和视频录制用**，不面向玩家，不接入玩家沙盘。
- **只在编辑器和开发构建中存在。** 正式构建里没有这些代码、没有按键响应，也不产生任何开销。
- 演示由团队在桌面会话里操作和录屏，评委不会自己上手玩。

### 1.3 一次完整演示流程（以场景 2 为例）

1. 在编辑器 Play 或开发构建里进入正式场景，启动导演并选中"遇袭挂起恢复"。
2. 导演把两台智能体摆到场景起点，切好焦点，打开 B 面板（演示模式）和 U 叠加层。
3. 导演以指挥员身份经地图正式入口给焦点智能体下达一条路线。面板第一步亮起：指令槽出现"指挥员"命令，状态机进入"沿路线移动"，行为树的移动分支亮起。
4. 导演让路线旁的敌人察觉智能体，敌人真实开火命中。面板第二步亮起：
   - 原命令进入挂起槽，反击命令占据活动槽；
   - 状态机沿"进入战斗"出边切换，出边上显示优先级 100；
   - 行为树依次点亮"评估射界 → 接近 → 开火"；
   - 叠加层画出视线射线和接近点两圈候选。
5. 敌人被击败。面板第三步亮起：挂起槽里的同一条命令回到活动槽，时间线标出"恢复"，路线从原来的第几段继续。
6. 导演写出本次事件记录，录屏素材里的每一步都有对应的运行记录可查。

### 1.4 完成后的交付形态

- 重构后的行为树及其构建代码，旧的大动作节点删除；`InteractLoot` 状态删除。
- 核心库扩展：响应式组合节点、记忆作用域、只读结构接口、结构化事件记录。
- 遥测层：零副作用，只在编辑器或开发构建中编译。
- B 面板、U 叠加层、导演和三个场景配置。
- 新增的回归用例组：等价对拍、库语义、遥测只读、禁用调用清单。
- 进入仓库的时长批跑工具，以及新的基线和重构后的对比记录。
- 文档更新：框架设计文档、框架图、README 中的相关说明。

### 2.2 已核实的关键源码事实

**状态机与行为树的现状**
- 状态机和行为树库都是项目自研的。层级为 根 → 局内 → 7 个叶子状态：探索、战斗、搜索资源、`InteractLoot`、撤离、侦查敌源、导航。
- 转移只看指令槽在黑板上的镜像。行为树只执行指令、只能结束指令，从不创建或替换指令。状态机不读行为树的结果。
- 各状态的树只有一两个节点：
  - 导航、侦查敌源：一个移动节点；
  - 战斗：一个交战节点；
  - 搜索资源、撤离：记忆序列套两个节点。
- 库里的选择器、装饰器、条件节点在游戏代码里都没用到。

**现有库的限制**（决定第一期必须先补库）
1. `SequenceNode` 和 `SelectorNode` 都是**记忆式**的：运行中的子节点下一帧直接续跑，不重查前面的条件。现有动作节点内部恰恰每帧从头重查全部条件，例如交战节点每帧先确认目标存活。直接用现有组合节点拆树，行为一定会变。
2. `RepeaterDecorator` 只能按固定次数重复，没有"重复直到满足条件"。
3. `BlackboardConditionDecorator` 在条件变假时不中断正在运行的子节点。
4. 子节点列表是受保护字段，外部无法遍历树结构。

**调试记录的现状**
- 每个节点每帧都写一条插值字符串，包括 `Tick => {result}`；记录存进满了就删除第一条的列表（O(n)），没有任何读者。
- 行为树上下文的调试记录不允许为空，传入空值会抛空引用；状态机那边做了判空。
- 状态转移只记了目标状态和转移名，来源状态和优先级都没记。
- 树拆细以后节点数会翻倍，这部分字符串分配会直接放大。

**挂起与恢复**
- 进度分三层保存：
  - 路线层：计划和游标在反击期间被冻结；
  - 资源层：全局登记簿记录本轮已处理的箱子；
  - 生命周期层：挂起槽本身。
- 节点内部的细粒度状态会重来：正在等待的背包会话、导航卡死检测、撤离倒计时。

**测试覆盖**
- 用例目录共 94 组、718 例。直接与大脑相关的有 27 组、228 例，外围还有约 110 例。
- 其中 3 组属于 Regression 套件，用 `-Suite Core` 跑不到：资源回访、资源命令完成、高台接敌。
- 测试代码里只有资源命令完成那组直接构造了行为树节点。

**`InteractLoot`**
- 进入条件从未成立。黑板键 `HasInteractableTarget` 只会被写成 false，却在 3 条转移规则里被读取。
- 测试、工具、用例目录里都没有引用它。

**副作用陷阱**（遥测禁止调用）
- 背包：汇总类方法会同步运行时状态，结算类方法会关闭会话。
- 资源群：待处理查询会刷新群状态，发出通知，并对每个成员算一次路径。
- 路线解析：事实查询、修订号读取、路线估算都可能推进修订号，从而改变重规划时机。
- 射击判定会覆盖"上次射击结果"。
- 带 `GetOrCreate` 的入口可能新建对象。
- `IAgentReadOnly.Blackboard` 返回的是可写黑板。

**现有调试工具的问题**
- 挂在 Agent 预制体上的调试面板在正式包里也启用，每 0.1 秒刷新一次，会触发资源群刷新和路径计算。
- 按 I 打印也在正式包里生效，并且和背包的 I 键冲突。
- 项目里没有任何"只在开发构建生效"的门控先例。唯一的条件编译宏是 `ANOMALY_SCENE_AUTOMATION`，只有场景自动化构建才会加。

**我在调参时引入的问题**
- 我当时新增的"读取背包价值"方法自称只读，实际上对在场智能体会同步装备槽的运行时状态，并且有内存分配。决策控制器每 0.5 秒调用它一次。
- 当时说它"无副作用"是错的，见第 9 节待决项 D2。

**科普界面可复用的部分**
- 面板底纹、终端图形、热点引线、背景图形是公开类，可以直接用。
- 配色、构造方法、动效时长是私有的。
- 中文 SDF 字体的字符集只从航天目录采集。

**输入与层级**
- 输入闸门只是一个布尔值，没有持有者；只有科普档案在用。
- U 键只在废弃场景的一个特效预览里出现过；B 键完全空闲。
- HUD 用 1920×1080 缩放。紧凑地图在右上角，占 380×350，层级 200；展开时层级 300；顶部反馈层级 350；科普档案层级 29000。

**三维绘制**
- 没有能进 Player 包的世界空间画线工具。
- 科普系统的叠加着色器支持穿墙显示，可以复用；layer 31 已被科普展台占用。
- 接近点候选只是查询函数里的局部变量。

**时长基线**
- 批跑脚本目前只在本会话的临时目录里，原始数据在验证克隆的 `Logs/RaidDuration/<批次>/` 下，种子记在各批次的 `study.json` 中。
- 基线结论：4 倍速 16 局，有效时长中位数约 178 秒，16 局全部双人撤离，0 阵亡。

### 2.4 本方案的默认值（随本规划一起 Review）

- **重构只改结构，不改行为。** 等价的定义见 5.1 节。决策公式、参数、转移规则、路线规则一律不动。
- 只重构行为树；路线执行层和指令生命周期保持原样，在面板里作为独立的两层显示。
- **门控：** 遥测、面板、叠加层、导演整文件包在 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 里；游戏代码里的挂钩调用点用同样的条件编译，正式构建不留调用。核心库的结构化事件记录是对现有字符串记录的替换，始终编译，按设计不分配内存。
- **按键：** B 打开或关闭面板，U 打开或关闭叠加层。科普档案打开时两者都隐藏、按键失效。面板非模态，不碰现有输入闸门。
- **视觉：** 沿用科普终端的蓝青配色，不用黄色和橙色强调。中文为主，节点类型下方配小号英文。
- **工作方式：** 在 dev 上逐阶段提交（同步工具只同步配置分支 dev，VPS 与验证克隆必须同在 dev）；每个大阶段先写小规划，实现后定向验证；不推进主项目、不推送 GitHub，除非用户另行要求。

### 2.6 验收目标

1. 对每棵重构的树做差分对拍：新旧两棵树在同一组脚本化输入下，逐帧的副作用记录完全一致。
2. 全量回归（`-Suite All`，不含 Maintenance）结果不差于重构前。会话 0 下跑不了的 4 个真实窗口组照旧排除。

   - 全部双人撤离，0 阵亡；
   - 有效时长中位数与基线相差不超过 10%；
   - 不出现新的卡住类型。
4. 遥测只读：同一组构造场景分别开、关遥测，智能体的副作用记录完全一致；禁用调用清单测试通过。
5. 性能：遥测关闭时，大脑每帧耗时不高于重构前，并且不再有逐帧的调试字符串分配。遥测打开时，稳态没有逐帧的内存分配；界面文字按 10 Hz 刷新时的分配不计入。
6. 正式构建里找不到遥测、面板、叠加层和导演的任何类型，B 和 U 键没有响应。
7. 三个导演场景在开发构建里各连续成功 3 次，每次都留下完整事件记录。
8. 面板和叠加层在桌面会话里通过人工目视验收（会话 0 跑不了真实窗口）。

## 3. 架构和职责边界

### 3.1 依赖方向

```
Core.BehaviorTree / Core.StateMachine      （库：组合节点、记忆作用域、结构接口、事件记录）
        ↑
Gameplay.Agent.AI                          （树构建、细粒度节点、树记忆；只依赖库和既有游戏服务）
        ↑ 只读挂钩（条件编译）
Gameplay.Agent.Telemetry                   （每个智能体一份记录器；LateUpdate 汇总；只读）
        ↑
Telemetry.UI（B 面板）   Telemetry.Overlay（U 叠加层）
        ↑
Gameplay.Demo（导演：只调用正式命令入口；读遥测判断步骤推进）
```

- 游戏代码不依赖遥测、界面和导演。挂钩以"可空接收器"的形式存在，接收器为空时什么都不做。
- 导演只经正式入口操作游戏，与玩家和自动化走同一条路：地图提交、命令路由、焦点切换、敌人察觉，以及布景时使用的导航瞬移。它不直接写黑板或指令槽。
- 遥测只调用 2.2 节确认安全的读入口，并由禁用调用清单测试强制约束。

### 3.2 四类数据必须分清

| 数据 | 来源 | 写入时机 | 读者 |
| --- | --- | --- | --- |
| 结构（静态） | 树和状态机实例 | 构建时一次 | 面板布局 |
| 运行状态（每帧） | 节点最近状态、当前叶子状态、本帧求值的出边 | 在原逻辑执行时顺手写入 | 面板高亮 |
| 过程记录（环形缓冲） | 决策轮次与候选拆项、接近点探测、视线结果、状态转移、指令与路线事件 | 写入点在原计算位置，不重算 | 评分表、叠加层、时间线 |
| 快照（每帧汇总） | 只读入口：路线快照、指令槽、黑板只读取值 | `[DefaultExecutionOrder(10000)]` 的 LateUpdate | 面板、导演步骤判断 |

## 4. 行为树重构设计

### 4.1 拆分原则

1. **原来同一帧内从头重查的逻辑，改用响应式组合节点；原来跨帧记住进度的地方，保留记忆式组合节点。** 例如撤离树外层"先到达、再驻留"的记忆序列保持不变，否则到达后的每一帧会多调用一次移动。
2. **条件节点必须是纯查询。** 有副作用或代价高的查询放进"评估"动作，结果写进树记忆，条件节点只读记忆。例如射击判定会覆盖"上次射击结果"，所以要放进"评估射界"动作，每帧只调用一次，调用位置与现在相同。
3. **执行记忆放进每棵树一份的记忆对象，不放进黑板。** 包括失视计时、接近点缓存、正在等待的背包会话、当前撤离点。写黑板会触发变更事件、推进版本号，等于改变行为。记忆由"记忆作用域"装饰器在树进入时重置，重置时机与现有节点的进入、退出、中断语义逐条对应。
4. **保持副作用的顺序和次数。** 每帧对指令接收器、注册表、事件通道、撤离计时、背包、科普投放计数的调用顺序和次数都不变。例如"通报交战"仍然每帧一次，并且在存活确认之后、射手检查之前。
5. **新节点不在逐帧路径上分配内存。** 失败原因使用静态字符串；节点名在构建时确定。

### 4.2 响应式组合节点的语义（P1 固化）

- **响应式序列。** 每帧从第一个子节点开始执行。
  - 某个子节点返回"运行中"：如果上一帧运行中的是排在后面的另一个子节点，先中断它，再返回"运行中"。
  - 某个子节点失败：中断上一帧运行中的子节点，然后返回失败。
  - 全部成功：返回成功。
- **响应式选择器（优先级回退）。** 每帧从第一个子节点开始执行。
  - 第一个返回成功或运行中的子节点胜出；如果上一帧运行中的是排在后面的另一个子节点，先中断它。
  - 全部失败：返回失败。
- **中断的触发时机。** 中断会调用节点的中断回调，而中断回调本身带副作用，例如撤离节点会清除撤离点登记、搜索节点会上报离开。所以"同一帧内，在哪个子节点返回之后触发中断"属于契约，由库语义测试固定下来。

### 4.3 各树草图（P2–P5 小规划定稿）

**导航、侦查敌源**

```
导航（响应式序列）
├─ 条件  智能体有效
├─ 条件  持有移动指令，且目标类型为位置
├─ 动作  解析目标位置          失败时结束指令（目标无效）
└─ 动作  移向目标              到达后结束指令（只有导航树这样做）
```

**撤离**

```
撤离（记忆序列，与现状相同）
├─ 前往撤离点（响应式序列）：条件 持有撤离指令 → 动作 解析最近撤离点 → 动作 移向撤离点
└─ 驻留撤离点（响应式序列）
   ├─ 条件  持有撤离指令
   ├─ 动作  解析撤离点          失败时结束指令（目标无效）
   ├─ 动作  移向撤离点          未到达时返回运行中，排在后面的"登记"会被中断，从而撤销登记
   └─ 动作  登记在撤离点内      每帧续写；退出或中断时撤销
```

**战斗**

```
交战 [记忆作用域：交战记忆]（响应式序列）
├─ 条件  持有交战指令
├─ 动作  同步指令记忆          命令变化时清零计时
└─ 处置（响应式选择器）
   ├─ 目标已结束：条件 目标丢失或阵亡 → 动作 收尾战斗（阵亡时通报击败）
   └─ 交战中（响应式序列）
      ├─ 动作  通报交战
      └─ 应对（响应式选择器）
         ├─ 攻击不可用：条件 射手未配置 → 动作 判定攻击不可用
         ├─ 动作  评估射界（视线和枪口，结果写入记忆）……
         ├─ 开火：条件 可开火 → 动作 停步并记为已观察 → 选择器（等待攻击冷却 | 释放技能 | 射击）
         └─ 接近：动作 更新失视计时 → 选择器
            ├─ 失视超时 → 判定失视
            ├─ 导航未就绪 → 直奔敌人地表点
            └─ 刷新接近点（求不出 → 判定不可达）→ 初次手动接近预算 → 移向接近点
```

"评估射界"在树中的确切位置要保证现有的调用顺序不变：先做视线检查，再检查射手，最后做枪口检查。具体在 P4 小规划里按调用顺序表核对。

**搜索资源**

```
搜索资源（记忆序列，与现状相同）
├─ 前往最近未处理成员（响应式序列）
└─ 处理资源群 [记忆作用域：搜索记忆；退出时按结果上报完成或离开]（响应式序列）
   ├─ 条件  持有搜索指令
   ├─ 动作  同步搜索目标
   └─ 按目标形态（响应式选择器）
      ├─ 资源群：解析下一成员（群已无待处理 → 完成搜索；不可达 → 判定不可达）
      │          → 切换成员时清空到达和等待 → 处理单个成员
      │          → 成员完成后：群已无待处理 → 完成搜索；否则转入下一成员（返回运行中）
      ├─ 抽象资源点：移向 → 完成
      └─ 具体对象：处理单个成员（完成时结束指令）

处理单个成员 =
  上报接近 → 移向成员（未到达：撤销等待、上报接近；离开范围时关闭本人背包）→ 停步
  → 战利品箱：登记科普投放并生成战利品 → 已处理 | 空箱（标记后完成）| 等待背包
  → 地面物品：已处理 | 无效（标记后完成）| 等待背包
  → 其他：完成

等待背包 =
  上报等待 → 无背包控制器时保持运行中 → 首次等待时通报触碰 → 观察匹配的会话
  → 容量不足：标记、通报完成、置"需撤离"、上报容量不足、完成搜索
  → 正常关闭：标记、完成本成员
```

"转入下一成员"的做法与现状一致：返回运行中，并且不退出根节点。如果改成先退出再进入，搜索记忆会被重置，"完成搜索"音效的去重标记也会跟着清零，行为就变了。

### 4.4 删除 `InteractLoot`

- 删除状态、四条出边、搜索资源指向它的一条转移、两条转移规则和状态工厂方法。
- 枚举只删掉这个成员，其余成员保留显式数值 5、6、7 不变。
- 删除黑板键 `HasInteractableTarget`，以及它的全部写入点和没有调用方的公开设置接口。
- 读取它的三条规则里，凡是只因它存在的分支按"恒为假"化简，化简前后的真值表要有测试覆盖。
- 同步更新调试面板、I 键打印、框架设计文档和框架图里的引用。

### 4.5 迁移顺序和开关

- 按风险从低到高迁移：导航和侦查敌源 → 撤离 → 战斗 → 搜索资源。
- 每棵树迁移期间，状态工厂有一个内部开关，可以选择新树或旧树，供对拍使用。开关不进配置资产，也不对外暴露。
- 一棵树通过对拍和定向回归后，就删掉它的旧节点和开关分支。
- 唯一直接构造旧移动节点的测试（资源命令完成组）随资源树迁移改为构造新树。

## 5. 等价性和回归验证

### 5.1 等价的定义

**必须完全一致：** 每一帧的这些副作用调用，按顺序、带参数。

- 对指令接收器：移动（目标、停止距离、速度）、停步、结束指令（命令 ID、失败原因）；
- 战斗：射击、施放技能、锁定攻击、攻击动画通知；
- 注册表：交战、击败、资源触碰、资源完成通知；
- 资源交互事件通道发布的事件；
- 撤离计时的进入和离开登记；
- 背包：关闭会话；
- 科普投放计数、战利品生成与标记、已搜登记；
- 黑板写入（键、值）；
- 搜索完成音效。

**还必须一致：** 根节点每帧的返回状态（运行中、成功、失败），因为它决定运行器什么时候重启树，从而决定进入时的重置。

**不要求一致：** 失败码和失败文本、节点名、调试记录的内容。

### 5.2 差分对拍工装（P2 建立，之后每棵树复用）

- **录制替身。** 一个同时实现只读智能体接口和指令接收器接口的替身，转发真实智能体的只读数据，记录所有调用。移动调用不转发给导航系统，而是按脚本返回导航结果，所以智能体的位置完全由脚本决定。
- **构造世界。** 沿用回归工具的构造世界：平面导航、工厂生成的敌人、资源群、撤离点。射线检测针对静态碰撞体，结果是确定的。
- **手动推进。** 用固定的帧间隔和显式时间直接推进运行器，不依赖 Unity 的帧时序。
- **全局通道的记录。** 资源交互事件、指令反馈、黑板变更（只在工装里订阅）、敌人血量、撤离计时状态，都在工装内记录。
- **场景脚本。** 每棵树至少覆盖它现有的全部分支：
  - 导航：到达、目标无效；
  - 撤离：到达、离开范围、目标无效、切换撤离点；
  - 战斗：目标丢失、阵亡、射手未配置、可开火、技能、冷却、失视超时、导航未就绪、求不出接近点、初次手动接近预算耗尽、命令切换；
  - 搜索：群完成、不可达、多成员轮转、空箱、已处理、等待背包、容量不足、中途离开范围、抽象点、具体对象、中断。
- **判定。** 新旧两棵树各跑一遍，比较记录序列。不一致时报告第一处差异的帧号和调用。

### 5.3 回归

- **每棵树迁移后跑定向组：**
  - 导航：导航执行、路线移动、地图命令；
  - 撤离：生命周期、撤离中断、撤离在场；
  - 战斗：感知、可达接敌、高台接敌、场景接敌与追击、反击进展、手动任务恢复、冷却；
  - 搜索：资源命令完成、资源回访、资源位移、场景背包、场景资源导航、群命令背包。

  其中资源命令完成、资源回访、高台接敌属于 Regression 套件，必须用 `-Group` 点名跑。
- **重构完成后：** 跑 `-Suite All`，排除 Maintenance 组和会话 0 下跑不了的 4 个真实窗口组，结果与重构前基线逐组对比。
- **时长批跑：** 转正后的批跑工具，用基线批次的同一组种子，在 4 倍速下跑 16 局，按 2.6 节第 3 条判定。

### 5.4 遥测零副作用

- **构造对拍。** 同一组差分场景分别在遥测开、关两种情况下运行，智能体的副作用记录必须完全一致。
- **禁用调用清单。** 一条测试扫描遥测、界面、叠加层、导演目录的源码，禁止出现以下调用：
  - 背包汇总和结算；
  - 资源群的待处理查询与最近可达查询；
  - 路线解析器的事实查询、修订号读取和路线估算；
  - 射击判定；
  - 带 `GetOrCreate` 的入口；
  - 对黑板的写入；
  - 指令生命周期的提交、结束、取消；
  - 导航代理的任何赋值；
  - 物理同步。

  导演的命令入口单独放行。
- **真实对局只做统计判定。** 真实对局的帧时序不确定，开、关遥测的整局对比只看时长批跑的统计结论，不要求逐事件一致。

### 5.5 性能与构建门控

- 给大脑每帧的推进加性能标记。用场景自动化自带的性能采集，比较重构前、重构后、遥测打开三种情况下的耗时和内存分配。
- 在会话 0 用批处理分别构建一个正式包和一个开发包：
  - 正式包：用反射清单确认遥测、界面、叠加层、导演类型都不存在；
  - 开发包：确认这些类型存在。

### 6.2 B 面板

**布局**
- 1920×1080 缩放，层级 280：高于状态 HUD，低于展开地图（300）和顶部反馈（350）。
- 常规布局放在右侧、紧凑地图下方。

- 两版布局在 P8 先出静态稿，由用户选定后再实现。

**子视图**
- **状态机：** 叶子状态排成节点图，转移用横竖直线连接，画法与沙盘一致。只展开当前状态的出边，每条出边标出优先级和本帧条件的真假。刚发生的转移沿线走一个光点。

- **指令槽：** 活动槽和挂起槽两个格子，每条命令标出来源：指挥员、反击或自主。另外显示路线快照，包括第几段和剩余群。

- **时间线：** 状态转移、挂起、恢复、完成、失败、选中目标变化，可以拖动回看最近的记录。
- **演示模式：** 顶部是三步标题和解说文案，用法照搬科普界面的播放、暂停、单步。步骤由导演根据推进条件切换。暂停时冻结游戏时间，面板动画使用不受暂停影响的时钟，照常播放。

**样式**
- 抽出一个公共的终端样式类，存放配色、字号、动效时长，加一条测试钉住它与科普界面的配色一致。科普界面本身不改。
- 字体生成器的字符来源加入新目录。重建字体后，面板的中文必须全部命中预烘焙字符。

## 7. 现场导演

### 7.1 设计

- 场景配置定义：步骤、推进条件、超时、该步的面板文案。推进条件借鉴场景自动化已有的命令剧本：就绪、移动中、反击中、战斗结束、背包打开或关闭、接近目标、完成。
- 场景自动化代码只在自动化宏下存在，开发构建里没有。所以导演自带一份精简实现，必要时把推进条件的判断抽成共享代码。
- 导演只使用正式入口：
  - 地图提交，让地图上能看到点击；
  - 命令路由；
  - 焦点切换；
  - 敌人察觉：让巡逻中的敌人察觉智能体，由敌人真实开火造成受击；
  - 布景用的导航瞬移，瞬移后同步物理。
- 每次运行先固定随机种子，保证同一场景可以重复拍摄。
- 事件记录写成 JSONL，包括步骤推进、遥测时间线、指令与路线事件，以及种子和场景配置的指纹。

### 7.2 三个场景

| 场景 | 布景 | 触发 | 三步 |
| --- | --- | --- | --- |
| 自主选目标 | 开局位置，自主模式 | 等待一次决策轮次 | 候选与拆项 → 选出最高分 → 规划图上路线并出发 |
| 遇袭挂起恢复 | 焦点智能体在一条途经巡逻敌人的路线起点 | 导演经地图下达路线，智能体靠近时敌人察觉 | 指挥员命令执行 → 受击挂起与反击 → 同一条命令恢复 |
| 指挥员干预 | 自主路线进行中 | 导演经地图提交另一个群 | 自主路线 → 指挥员点群 → 原路线被替换，新路线执行 |

背包等待由导演自动代操作（D4）。面板只负责演示界面，剪辑时和实机画面搭配，所以导演的目标是稳定地制造出上表中的时刻，不要求面板步骤和视频片段逐一对应。

## 8. 分阶段闭环

每个大阶段都按同一个流程走：写小规划 → 实现 → 定向验证 → 自查（必要时做架构审查）→ 汇报 → 用户授权后提交。

| 阶段 | 内容 | 退出条件 |
| --- | --- | --- |
| **P0 基线与审计** | 批跑工具转正进仓库；按 D1 方案 b 处理现有调试面板和 I 键打印；审计并处理 D2；固定禁用调用清单；用基线批次的同一组种子重跑 16 局，形成新基线，并与旧基线对比 | 新基线数字落盘；D1、D2 的改动有对拍或回归证据 |

## 9. 风险、取舍和待决项

### 9.1 待决项（已于 2026-10-19 决定，结论见 2.3 节，以下保留决策时的背景）

- **D1 现有调试面板的副作用。** 它在正式包里每 0.1 秒刷新一次，会触发资源群刷新和路径计算。现有游戏行为和调参数据都是在它开着的情况下得到的。
  - 方案 a（推荐）：重构期间保持原样，P6 之后再单独决定。
  - 方案 b：改为只在编辑器和开发构建中启用，并改用安全读入口。正式包的行为会因此变化，需要重新跑一次时长基线。
- **D2 "读取背包价值"的副作用（我引入的问题）。** P0 先审计这次同步会不会改变任何可观察的状态。
  - 如果不会：改成真正只读的实现，并用决策轮次记录比对，确认分数逐位一致。
  - 如果会：向你说明影响后再决定。
- **D3 面板布局。** P8 出两版静态稿，由你选定。
- **D4 导演场景中的背包操作。** 导演自动代操作，还是由真人操作，在 P10 定。
- **D5 提交授权。** 每个大阶段验收后是否授权提交到功能分支；P6 是第一个建议提交点。

### 9.2 主要风险

| 风险 | 应对 |
| --- | --- |
| 响应式组合节点的中断时机和原逻辑不同，产生隐蔽的行为差异 | 库语义测试固定中断时机；差分对拍逐帧比对副作用 |
| 搜索树分支多，涉及背包会话、交互事件和科普投放计数 | 放在最后迁移；对拍场景覆盖所有分支；资源位移组断言精确事件序列；科普投放计数测试必跑 |
| 真实对局不确定，批跑数字有波动 | 用同一组种子，按统计阈值判定；出现新的卡住类型就逐局排查 |
| 遥测误调用有副作用的方法 | 禁用调用清单测试，加遥测开关对拍 |
| 面板在会话 0 无法截图验收 | 人工目视验收，并提供核对清单 |
| 字体缺字 | 字体生成器扩展字符来源，加缺字检测测试 |
| 导演在开发构建里依赖的场景自动化代码不存在 | 导演自带精简实现，不依赖自动化宏 |

### 9.3 已放弃的方案

- **只暴露"节点内部阶段"、不拆树（方案 A）：** 用户选择了方案 B。
- **只回放记录驱动演示：** 用户选择现场导演；事件记录照样留存。
- **让面板共用现有输入闸门：** 闸门没有持有者，会和科普档案互相释放。
