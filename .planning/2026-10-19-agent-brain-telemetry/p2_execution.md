# P2 对拍工装与低风险树：执行记录

目标见 [大规划](task_plan.md) 第 4.3、5.2 节和第 8 节 P2。

## 1. 对拍工装

位置：`Assets/Scripts/Editor/AgentReproduction/Brain/`。

- **录制替身 `RecordingAgent`**：同时实现只读智能体接口和指令接收器接口。只读数据转发给真实智能体；所有命令都写入记录。移动不交给导航系统，而是按脚本返回导航结果，默认规则是平面距离在停止距离内即"到达"；智能体位置完全由脚本瞬移决定。结束指令时按生命周期的做法清掉黑板上的待处理指令，并记录是否命中当前命令。
- **运行器 `BrainTreeHarness`**：用独立黑板（从真实智能体复制移动和攻击参数）和固定步长 0.1 秒、显式时间推进行为树，整段脚本在一帧内同步执行，不受 Unity 帧时序影响。记录内容：每步标签、每帧根结果、替身收到的全部命令（含参数和返回）、黑板每次变更（键和规范化的值）。
- **判定**：新旧两棵树各在同一个真实智能体上跑同一段脚本，记录逐行比较，不一致时报告首处差异的行号和前后文。另外每个场景检查旧树记录里确实出现了该场景要覆盖的关键行，防止脚本没走到分支也"通过"。

后续阶段在此基础上加入资源交互事件、敌人状态、撤离登记等记录项。

## 2. 树的迁移

**旧树**：导航、侦查敌源都是单个 `MoveToTargetActionNode` 作为根，差别只在目标类型和到达后是否结束指令。

**新树**（`AgentBrainTrees.Navigate` / `InvestigateEnemySource`）：

```
沿路线移动 / 侦查敌人来源（响应式序列）
├─ 条件  智能体可行动
├─ 条件  持有移动指令（目标类型：路线锚点 / 敌人来源）
├─ 动作  解析目标点          失败时按目标无效结束指令；搜索指令且目标已完成时清除指令并返回运行中
└─ 动作  移向目标点          到达返回成功；导航树到达即结束指令
```

逐项对照旧节点的执行顺序：取智能体 → 取指令 → 校验目标类型 → 按目标类型解析位置 → 读速度和停止距离 → 移动 → 到达后结束指令。新树把前三步拆成两个纯查询条件，解析和移动拆成两个动作，中间通过本树一份的移动记忆传递目标点和命令 ID。响应式序列每帧从头执行，和旧节点每帧从头重查一致；只有移动节点会返回运行中，没有需要中断的兄弟节点。

**旧树保留位置**：`AgentLegacyBrainTrees`，迁移期间供对拍；全部迁移后移出运行时代码（P5 定方式）。

**附带改动**：
- `AgentActionNodeBase` 的取智能体、取指令改为调用共享的 `AgentTreeQueries`，逻辑不变。
- 探索树的占位节点缓存宏状态名字符串；黑板值相同时本来就不触发变更，行为不变，少一次逐帧分配。

## 3. 验证

`BrainTreeEquivalence` 组：导航 6 个场景（到达并结束、中途换目标、目标无效、目标类型不符、指令类型不符、无指令），侦查敌源 3 个场景（到达后保持、目标类型不符、目标无效），以及状态工厂已改用新树的检查。

**结果**：首轮（`65fc320`，p2-b）新旧记录全部一致，但 3 个场景的覆盖检查失败：脚本把智能体放在目标 1 米处，而真实移动停止距离是 0.25，到达从未发生。修正后（`1f583a6` 起）连同撤离、战斗一起在 p4-d（`fe261b5`）24/24 通过，每个场景的关键行都出现。导航相关定向组见 P1 结果。

工装上的两处修正：替身的到达判定改为与导航查询一致（容差取到达容差 0.1 和停止距离中的较大者）；瞬移按地面点加上导航基准偏移（`Warp` 直接写入身体位置，原来把身体放在地面以下）。
