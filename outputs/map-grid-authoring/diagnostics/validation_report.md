# 地图摆放冲突诊断修复

2026-09-13。实现和架构审查完成，39 项定向测试全部通过。

## 报错的含义

截图属于布局校验失败。名称是固定在 Zone 中央的矩形避让区，群图标不能覆盖它，横竖直线不能穿过它或其他群图标。校验检查旧线，固定位置生成只换线、不移动群，有限微调也可能在锁定条件或预算内找不到解，因此三个入口可能同时失败。

截图中 NodeOverName 对应：员工食堂 / EnemySourceCluster_A、员工宿舍 / ResourceCluster_A、实验室 / ResourceCluster_A、奇点塔 / EnemySourceCluster_B。两条 NonOrthogonalEdge 分别连接“奇点塔 / EnemySourceCluster_A ↔ 雨林 / ResourceCluster_C”和“龙骨礁 / EnemySourceCluster_B ↔ 龙骨礁 / ResourceCluster_B (1)”。名称按本轮源图资产的稳定 ID 解析，用户内存草稿的位置未被改写。

## 修复与使用

- 诊断改为可滚动的逐条中文说明，显示区域名、群名或连接端点，提供定位、相关障碍高亮和处理建议。悬停及“复制完整诊断”仍保留机器代码和 ID。
- 画布显示名称避让框；编辑、Undo/Redo、取消和新任务会清理旧诊断。只读诊断不增加导航查询或搜索，不改世界物体。
- 微调失败原来显示未采用候选的问题，现改为当前初始摆放的问题。构造样例搜索 9 个布局，最少 2 项冲突，原摆放有 3 项；失败仍正确报告原来的名称遮挡。
- 构造测试发现草稿和工作图通过浅拷贝共享内部节点，Unity Undo 可能连带修改工作图。修复为在 MapGraphPlacementState 接收布局时取得独立序列化数据副本。保留失败 XML，修复后验证 8 轮撤销/重做，草稿恢复正确，工作图不变。

遇到当前报错，先点“定位”将群移出名称框，处理人工线和图标阻挡，再“生成连接 → 应用预览 → 发布地图”。旧自动线会重新筛选，人工线和样式线继续保留作者约束，需要明确调整、重绑或删除。校验仍会拒绝真实几何冲突；本次没有覆盖用户正在摆放的地图草稿。
