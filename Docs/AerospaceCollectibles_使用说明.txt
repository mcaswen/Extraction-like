航天零件搜集与科普 — 接入说明（更新至 2026-10-09）

一、正式入口
Unity 2022.3.62f2c1，项目内打开：
Assets/Scenes/Scene_DB/Scenezl_Final 1.unity
进入 Play 后搜集系统自动启用，不需要手动拖挂脚本。领取按钮与“航天档案”界面一起创建，不依赖编辑器中缓存的场景对象；开局不会自动发放零件。

调试领取：左下角“航天档案”上方的“领取五个飞船零件”按钮，点击后向当前焦点 Agent 的背包补齐 R01～R05，每种一个。
每个 Agent 每局每种只领取一次；背包已有的种类不重复添加，已领取后丢弃或转出也不补发。空间不足时先加入能放下的零件，清出空间后再点即可领取剩余种类。
领取后解锁档案，不自动连续打开五个科普窗口。Play 模式下的按钮对象为 Aerospace_Collection_And_Science/Aerospace_Archive_Canvas/Grant_Five_Ship_Parts，位置在 AerospaceScienceUI.Layout.cs 中调整。
档案解锁保存在 PlayerPrefs 的 ASTRA_ScienceArchive_v1 键中，跨局保留；“历史归档”不代表本局背包里有该物品，也不代表开局再次发放。入口的“本局 0/5”只统计本局成功拾取的种类。

二、五种零件
R01 再生冷却喷管组件
R02 涡轮泵转子组件
R03 燃烧室喷注器组件
R04 可折叠栅格舵组件
R05 载荷分离机构弧段
物品 ID 为 ASTRA_R01 至 ASTRA_R05，均占 1 格，不堆叠；使用当前精修模型渲染的真实图标。

三、玩家如何体验
1. 左下角“航天档案”按钮，或 J 键，打开档案。
2. 点左侧底部“搜集线索”，可看到本局已探索的新箱数量、后续样件出现的搜索次数，以及已出现样件所在的资源区和箱子。
3. 沿用现有 Agent 搜索、开箱流程。首次实际搜索的新箱必有一件航天零件；实际投放后箱名追加“航天样件”。不会新放实体道具阻挡道路。
4. 等搜索和揭示动画完成，拖入背包，或 Ctrl + 鼠标左键快捷转移。
5. 只有成功放入当前 Agent 背包后才解锁：播放原创稀有发现音效、显示放大的组件图，收缩并交叉淡入可旋转的真实 3D 模型。
6. 五个零件统一使用纸色科普侧栏与深橄榄色模型展台。默认先显示“整体介绍”；左侧可切换“工作原理 / 结构细节”，顶部五张档案卡切换已解锁零件。
7. 按住左键旋转，滚轮缩放。“完整结构 / 结构剖面 / 分解观察”可切换；“重置视角”恢复默认。点击模型上的 01～04 编号或左侧结构编号，镜头轻微靠近，并在左侧解释；“热点”按钮控制模型编号的显隐。
8. 默认使用 2K 贴图，点击模型工具栏最右侧的小齿轮打开“展示设置”，可切换 4K。鼠标悬停齿轮显示名称；点击空白处或按 Esc 收起设置。两档都使用同一套精修 LOD0 几何。
9. 可切换清理后样件 / 回收痕迹。R03 有放大“单元详解”，R04 可折叠，R05 可按“连接关系”依次看约束、解除约束、上下分开。
10. Esc、J 或右上角按钮关闭。若从背包拾取进入，会先返回背包；再按原来的方式关闭背包继续游戏。
11. 已解锁内容可在局内按 J 再次查看，或双击背包里的对应零件。档案跨局保存；下一局的收集进度重新从 0/5 开始。
12. 模型工具栏的黄绿色“原理演示”按钮带播放图标、悬停和按压反馈；正文中的演示入口使用深色实心按钮。演示展示当前零件的三步过程，可播放、暂停、按步骤查看或退出。退出时恢复之前的阅读页、局部选择、旋转缩放、折叠/放大单元/分离状态。
13. “展示设置 > 减少动态效果”关闭自动入场扫描、平滑过渡与演示自动播放；仍可主动播放或按步骤查看。偏好会保存。
14. 首拾入场可点“跳过入场”。进入阅读、换模型或关闭窗口会停止当前教学演示，阅读时模型不会自行转动。
15. 中文文字使用独立 Canvas 上的 TextMesh Pro SDF 字体；齿轮、播放图标以矢量绘制。模型独立画面按实际显示尺寸调整超采样分辨率，常规窗口为 2016×1190，4K 屏幕最高 3456×2040，开启 4 倍 MSAA，并在关闭档案时释放。界面文字不经过模型画面的缩放，也不受场景后处理影响；2K/4K 选项只控制模型贴图精度。

四、“保底”的具体含义
每局初始化后，使用场上 Agent 的真实导航配置核验现有资源群中的可达箱子，预留五种零件的搜索节奏，而不是立即把五件塞进附近的箱子。
正式场景默认在两名 Agent 合计探索的第 1、4、7、10、13 个不同箱子中，依次保底投放 R01～R05；每两次零件发现之间隔两个普通新箱，不依赖随机概率或等待时间。
只在 Agent 实际到达并执行搜索，或玩家正式打开箱子时计数。目标评估、GetSavedItems、提示预览、创建会话快照不会推进计数；重复打开、两个 Agent 搜同一箱、切换焦点均不会重复计数或补发零件。
后续零件跟随实际探索路线注入当次新箱，不要求回头开已搜过的箱子，也不改变原来的随机普通战利品规则。只有实际投放的箱子才增加一行运行时空间，普通物品、格子状态和原有搜索进度全部保留。
首次搜索保证的是“箱中有零件可搜取”，不是自动塞进背包。跳过未拿的样件后，它仍留在原箱，不会在下一个箱子再复制一件；线索页记录其位置。
不接管 Agent，不禁止死亡或撤离。正常搜集仍需实际前往搜索并拾取；调试领取按钮独立于搜索投放节奏。
背包满时保持原有拒绝转移行为：零件仍在箱子里，不提前解锁、不误播发现音效。清出空间后再拿。
两个 Agent 的物理背包保持独立，科普解锁和本局种类进度共享。已收集物品来回转移不会反复触发首拾动画。
如果未来地图只有 5～12 个可达箱子，五次投放自动在可用箱数内均匀分布（例如 9 个箱子时为 1、3、5、7、9）。少于五个可达箱子时，系统显示核验失败并输出明确错误，不会伪造“已保底”。正式场景使用标准的 1、4、7、10、13 节奏。

六、后续调整
科普文案与热点：修改 PartsCatalog.json；热点名称必须与导出的锚点匹配。
UI 排版：AerospaceScienceUI.cs，与原背包界面分开。
终端样式与动效：AerospaceScienceUI.Layout.cs、AerospaceScienceUI.Terminal.cs、AerospaceInspectionStage.Analysis.cs。
拾取音量：AerospaceCollectionRuntime.cs 中 discovery.volume，当前为 0.85。只影响航天零件首拾提示，不要调整 AudioListener.volume 来增强单个音效。
投放间隔：同文件 PreferredSearchStride，当前为 3。修改后应重跑 AerospaceCollectiblesTests；PrepareSearchedBox 是搜索计数的唯一入口，不要放进 GetSavedItems 或 AI 目标评分函数。
更换模型后，在 Unity 菜单 Tools > Aerospace > Rebuild collectible assets (no scene changes) 重建；再执行 Rebuild enlarged injector teaching element 重建喷注单元。
不要直接删除新脚本目录：原背包的成功拾取回调已引用这些类型。撤回应按完整变更一起撤回，不要删除原场景或原背包文件。

资产检查包括五个 Item、五个图标、2K/4K 共十个精修 Prefab、PBR 贴图、喷注教学单元和音效。
2026-10-09 在隔离副本通过 28/28 项自动检查：14 项搜集检查（含正式场景、领取按钮和真实背包链路），以及 14 项科普呈现检查。覆盖五个零件的阅读、热点、演示、缩放与设置，验证齿轮提示、设置收起、否定式文案清理，以及 1366×768、1280×1024、1600×900、1920×1080、2560×1080 和 3840×2160 的画面布局。4K 放大及恢复小窗口时，会核验模型纹理尺寸、相机与 UI 引用一致，关闭后释放显示资源。
这些是有边界的验证，不等于“任何情况下绝对没有 Bug”，不覆盖完整对局压力测试或所有显卡、分辨率。

八、素材与协作
音效由本项目混音设计，结合 Kenney Impact Sounds 的 CC0 物理触点与原创短噪声层，突出清脆起音和短促低中频重量；不再使用固定音高的长共鸣。来源与许可在 tools/audio/sources/kenney-impact/，选定母版在 sources/approved/。没有复制三角洲行动游戏音频。
正文字体为 Noto Sans CJK SC，来源 https://github.com/notofonts/noto-cjk，随附 SIL OFL 1.1；发布时保留字体许可。
终端英文与编号使用 JetBrains Mono，来源 https://github.com/JetBrains/JetBrainsMono；许可与版权说明同置于 Fonts 目录。
科普为虚构游戏教学样件，不对应具体发动机型号、制造尺寸、真实流场或运行参数；每件组件的来源链接保存在 catalog 中。
新增 FBX、PNG、WAV、OTF 由仓库现有 LFS 规则覆盖。团队拉取时请启用 Git LFS；提交时需一并提交相关资源、全部 .meta、新脚本、物品数据库追加项及最小接入修改。
协作与交付按仓库 AGENTS.md 执行：已确认的项目改动在验证后提交，并合入原仓库 dev 分支。保留其他成员提交和无关的本地修改，不使用强制推送。
